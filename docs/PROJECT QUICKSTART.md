# PROJECT QUICKSTART

## Проект

«Арена» — Telegram-бот и Mini App для самостоятельной подготовки к ЕГЭ по информатике.

Первый игровой маршрут на Staging включает карту из 27 заданий, ранги, Ядро Цитадели и испытание №11 с практикой. Production пока использует интерфейс v5. [Состояние релизов](PROJECT%20CONTEXT.md#последние-проверенные-релизы)

Репозиторий: `IvanIlinov/kimi`.

## Технологии

- Backend: Node.js, TypeScript.

- Frontend: Preact, TypeScript, Vite.

- База данных: SQLite (`node:sqlite`).

- Интеграция: Telegram Bot API и Telegram Web Apps API.

- Инфраструктура: VPS, Caddy, systemd; frontend размещается на Vercel.

## Структура

- `src/` — Backend, API, бизнес-логика и работа с БД.

- `web/` — Frontend Mini App.

- `data/` — данные приложения.

- `deploy/` — примеры конфигурации развёртывания. Текущие адреса и команды приведены в Project Context.

- `docs/` — Quickstart, технический контекст и роадмап.

Основные точки входа:

- `src/index.ts` — запуск Backend.

- `src/db.ts` — база данных.

- `src/logic.ts` — бизнес-логика.

- `src/api/` — HTTP API.

- `web/src/App.tsx` — корневой компонент Mini App.

## Локальный запуск и проверки

Нужен Node.js 22.18 или новее. Из корня репозитория установи зависимости backend и Mini App:

```bash
npm ci
npm ci --prefix web
```

Проверки из корня репозитория:

```bash
node --disable-warning=ExperimentalWarning --test src/*.test.ts src/api/*.test.ts
npx --no-install tsc --noEmit
npm run build --prefix web
```

Тесты и сборка запускаются без Telegram-токена. Для запуска backend с ботом
создай локальный файл `.env` с настройками тестового окружения и выполни `npm start`.

| Переменная | Назначение | Пример без секретов |
| --- | --- | --- |
| `BOT_TOKEN` | Обязательный токен тестового бота | `<токен тестового бота>` |
| `ADMIN_IDS` | Обязательные числовые Telegram ID администраторов через запятую | `111111,222222` |
| `MINIAPP_URL` | HTTPS-адрес Mini App, который открывает бот | `https://miniapp.example.test` |
| `STAGING_PREVIEW_ENABLED` | Включает предпросмотр гостя и ученика в Mini App. Задавать только в тестовом окружении | `1` |
| `API_PORT` | Порт API. При 0 API отключён | `3000` |
| `API_HOST` | Адрес, на котором слушает API | `127.0.0.1` |
| `ALLOWED_ORIGINS` | Разрешённые адреса фронтенда через запятую | `https://miniapp.example.test` |
| `DB_PATH` | Путь к отдельной локальной базе | `data/local.db` |
| `GROUP_CHAT_ID` | Telegram ID тестовой группы для групповых функций | `0` |
| `VITE_API_URL` | Адрес API для сборки фронтенда, задаётся в окружении Vite или Vercel | `https://api.example.test` |

## Предпросмотр Mini App

- **Три интерфейса ученика.** Команда `npm run demo --prefix web -- --student-layouts` собирает `student-minimal.html`, `student-balanced.html` и `student-full.html` в `web/demos/`. Во всех трёх доступны те же данные и сценарии. Меняются оформление и расположение блоков штаба.
- **В обычном браузере.** Из корня проекта выполни `npm run demo --prefix web` для демо ученика, `npm run demo --prefix web -- --admin` для демо администратора или `npm run demo --prefix web -- --guest` для демо гостя. Открой соответствующий файл в браузере: `web/demos/student-home.html`, `web/demos/admin-home.html` или `web/demos/guest-home.html`. Повторная сборка обновляет соответствующий файл. Демо используют вымышленные данные. Изменения в демо сбрасываются после обновления страницы. Для сохранения реальных данных нужен тестовый бот.
- **Игровой маршрут.** В демо ученика закрой окно итогов и посмотри эмблему ранга и Ядро на верхней плашке штаба. Затем открой «Миссии», выбери №11 во «Вратах» и нажми «Начать испытание». Реши пять задач за 10 минут, чтобы открыть «Практику». После десятого верного ответа в практике задание закрепится.
- **Кристалл недели.** В демо у Леры 17 задач за неделю. Во время учебного года нажми «Журнал задач» на карте, добавь `+10` и дождись вплетения кристалла. Можно также зажечь его решёнными задачами из практики №11. В штабе нажми на Ядро, чтобы посмотреть руны месяцев, три сезонных сегмента и прошлогодний узор. Для независимой проверки сценариев перезагрузи демо.
- **Навигация на телефоне и компьютере.** Команда `npm run demo --prefix web -- --swipe-navigation` собирает два локальных демо с вымышленными данными. Открой `web/demos/student-swipe-mobile.html` для свайпа с точками или `web/demos/student-swipe-desktop.html` для круглых стрелок.
- **Карточки итогов.** Открой [автономное демо](../web/demos/period-recaps.html) и выбери период. В карточках используются вымышленные результаты.
- **Итоги на главной ученика.** В [демо ученика](../web/demos/student-home.html) при загрузке открывается завершённая неделя. После закрытия перейди на левую страницу свайп-карточки и выбери «Неделя», чтобы открыть текущую. Внутри Pop-up можно листать периоды по кругу. Для демонстрации автопоказа сезона или года добавь к адресу файла `?recap=season` или `?recap=year`. В гостевом демо итоги доступны из профиля в рейтинге.
- **Варианты размещения.** Команды `npm run demo --prefix web -- --recap-swipe` и `npm run demo --prefix web -- --recap-button` собирают отдельные демо для сравнения левой страницы и кнопки рядом с месяцем. В Mini App используется левая страница.
- **В Telegram.** На Staging открой тестового бота, отправь `/start` и нажми «Открыть Арену». С аккаунтом ученика проверь «Миссии» → «Задание №11» → «Начать испытание». Закрой и снова открой окно, чтобы проверить таймер и сохранение прогресса. Администратор может посмотреть интерфейс ученика или гостя через предпросмотр. Для прохождения испытания нужен тестовый аккаунт ученика. [@rin_progress_bot](https://t.me/rin_progress_bot)

- [Staging](PROJECT%20CONTEXT.md#выкладка-в-staging) — сначала проверить изменения через тестового бота.
- [Production](PROJECT%20CONTEXT.md#выкладка-в-production) — после отдельного разрешения перенести проверенный коммит в `main`. Для изменений БД порядок резервного копирования и прогона миграций описан в том же документе.

Два учебных маршрута, этапы разработки, экраны и лестница рангов описаны в [роадмапе](PROJECT_ROADMAP.md#два-учебных-маршрута).

## Важные правила

1. Не изменять Production и не выполнять операции на Production без явного разрешения.

2. Не выполнять `commit`, `push`, `merge` и другие Git-операции, изменяющие удалённый репозиторий, без разрешения.

3. Не раскрывать содержимое `.env`, `.env.staging`, токены, секреты и приватные идентификаторы.

4. Не перезаписывать и не удалять пользовательские изменения.

5. Перед изменениями изучать соответствующий код и связанные тесты.

6. После изменений выполнять подходящие проверки.

7. Не считать документацию точнее актуального кода и тестов.
